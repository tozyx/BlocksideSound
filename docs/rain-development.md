# 材质雨声开发与试听

当前已实现共享配置、受雨表面采样、概率调度、空间播放及植物滴水。设置 GUI、室内遮挡混音和原版背景强度调节尚未实现。

## 已接入的声音

- 木质、金属、玻璃、植被、沙砾、水面、柔软表面各三个短变体；植物滴水另有三个变体，共 24 个单声道 Ogg Vorbis。
- 来自用户提供的 The Sound of Rain 音频提取目录。材质片段自动选取约 0.9 秒的较高能量窗口，植物滴水保留最长 0.5 秒；带 4 ms 淡入和 25 ms 淡出。它们是首轮候选，未经人工试听；长录音截取不代表已经得到孤立的单滴声。
- 不同位置的独立实例形成空间混音；一个事件随机选一个素材，不一次叠加所有变体。
- 所有声音走原版 WEATHER 天气通道，使用世界坐标、距离衰减与 0.95–1.05 的轻微随机音高。Mod 总音量 × 雨声功能音量 × 材质音量 × 当前雨强作为传入增益；Minecraft 引擎应用主音量和天气音量，代码不重复相乘。
- 第一版完整保留原版雨声作为背景。缺少音频的石质/陶质/地面、未知材质、被禁用或排除的材质继续听到原版雨声；不会把这些方块再归到别的材质。植物滴水独立，禁用后直接停止新增滴水。

## 配置与采样

- 首次初始化生成 `config/blocksidesound-client.json`；两平台开发环境分别位于模块 `run/config`。旧 `blocksidefoley-client.json` 的有效配置可自动迁移，旧文件保留。
- 修改文件后按 **F3+T** 重载配置与资源。解析失败保留最后有效设置和损坏文件原文；有效配置重载会停止已有本 Mod 音源、重建规则/采样/调度缓存。
- 默认水平半径 12、垂直范围 16、每 4 tick 至多扫描 64 列。原版高度图、局部降水、形状与流体高度用于识别表面，只查已加载区块；每次播放前重新查实际顶面。活跃音源也复核，表面被遮挡/改变或移出范围时停止。
- `rain.overrides` 支持明确 ID/tag 指定材质；明确 ID 优先于 tag，同级按列表次序。每类 `exclude` 支持 `namespace:block` / `#namespace:tag`，使用客户端可见的服务器同步标签。
- 扫描和播放分开。每个 8×8 的 X/Z 区域、每种材质各有一次调度计时；植物滴水独立。概率按有效尝试计，不按方块数、扫描次数或帧数计。默认材质概率 0.35、尝试间隔 10 tick，植物滴水概率 0.25、间隔 40 tick；群体密度和试听结果仍需调校。
- 第一次尝试随机错峰；同组已有音源时不叠加；同时最多 `rain.maxActiveSounds`（默认 8），每种音效最多 2 个，每 tick 最多启动 2 个、同种只启动 1 个。混合场景优先给较久未发声的类别机会，小面积材质不会单纯被大面积材质的方块数淹没。
- 声音自然结束后释放预算。切换世界、远距离传送、停止下雨、关闭功能/将其音量置零、主/天气通道静音或重载配置时停止本 Mod 的音源。
- 内置声音衰减距离 16 格，超过此距离的样本不占播放预算。检测半径增大不会自动扩大可听距离。

配置示例（在完整配置中修改对应字段）：

```json
{
  "volume": 0.8,
  "rain": {
    "enabled": true,
    "volume": 0.7,
    "radius": 12,
    "maxActiveSounds": 8,
    "debugLogging": true,
    "debugParticles": true,
    "materials": {
      "metal": {
        "enabled": true,
        "volume": 0.8,
        "triggerProbability": 0.35,
        "attemptIntervalTicks": 10,
        "exclude": ["minecraft:iron_block", "#minecraft:anvil"]
      }
    },
    "plantDrips": {
      "enabled": true,
      "volume": 0.6,
      "triggerProbability": 0.25,
      "attemptIntervalTicks": 40,
      "exclude": []
    }
  }
}
```

## 测试世界试听

1. 启动任一开发客户端，建立允许命令、位于平原等可下雨群系的测试世界。先执行 `/weather rain`；雷雨暂不新增雷声。
2. 在玩家附近不同方向准备木板、铜块、玻璃、砂、水面、羊毛、树叶或垂滴叶，各自露天；石头作为原版背景对照。测试同种材质左右位置时可跨 8×8 区域边界布置。
3. 调节原版天气音量，确认材质声与滴水均随其变化；修改 Mod 总/雨声/材质音量并 F3+T，检查作用范围。开启字幕可见中/英文材质提示。
4. 开启 debugLogging/debugParticles 并重载。日志包含 `Rain scan:` 和 `Rain play:`，后者显示事件、真实位置、增益及活跃数，不能超过配置上限。粒子每批最多 8 个；木质棕、金属黄、玻璃青、植被绿、水面蓝，其余白、排除/禁用/未知红。
5. 对比水面柔和撞击与植物滴水；确认植物滴水不是水面声音的另一随机变体。当前自动裁剪只是候选，需要人工评价是否符合目标。
6. 把 metal.exclude 加入 `minecraft:copper_block` 或对应 tag 并重载；铜块保持金属分类，停止增强。禁用 foliage 后仍可听植物滴水；另外禁用 plantDrips 后滴水停止。
7. 在某表面上方放屋顶、替换其方块、走出范围或传送，检查旧位置不再发声。移动到无降水/下雪群系时不新增雨滴声。再测试退世界、重新进世界、切换维度及暂停/继续。
8. 将概率设为 0 和 1：0 不触发，1 仍受冷却、同组去重、音源预算约束。概率为零与关闭材质都不影响本阶段保留的原版背景。
9. 关闭 rain.enabled 并重载，已有增强声立即停止，原版雨声仍在；再次开启能正常恢复。
10. 如只想试听单个素材组，可在允许命令的世界执行 `/playsound blocksidesound:rain.wood weather @s ~ ~ ~ 1 1`，并替换事件后缀。该命令不经过本 Mod 的概率/预算，不用它验收调度密度。

## 补充材料音频

共享目录为 `common/src/main/resources/assets/blocksidesound/sounds/rain/`；声音清单为同命名空间下的 `sounds.json`。固定事件后缀为：

`stone`、`wood`、`metal`、`glass`、`ceramic`、`foliage`、`ground`、`granular`、`water`、`soft`、`plant_drip`。

例如补石质素材时加入单声道 OGG，并定义 `rain.stone` 的 sounds 数组。重载后会自动检测事件可用性；没有定义/空事件不会播放，也不占调度预算。补充对应字幕、素材来源和许可记录。资源包也可使用相同命名空间覆盖事件。

## 验证边界

单元测试覆盖配置、材质解析、扫描计划、调度概率边界、时序、去重/预算、空间分组、小面积材质及新增事件可用性。两个加载器构建、jar 资源校验和短时客户端启动另行记录；这些都不能替代真实雨天世界的空间听感/遮挡/音量验收。

每列仍以中心点检查形状，复杂模组植物、稀疏形状和高度差需要场景测试。没有逐滴物理模拟、独立室内低通效果、原版背景抑制、雨后滴水或设置 GUI。
